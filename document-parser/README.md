# PDF / DOCX offline extraction core (04E A)

This is the first isolated A component. The six Document HTTP operations remain frozen, current production remains 22 operations / Target5 / four images. No Compose service, upload UI, RPC, active configuration, SQL or persistent parse queue is activated by this component. 小张 owns implementation and acceptance. Contract approval and main verification are recorded in [the component report](../reports/changes/04E/parser-core-2026-11-13.md).

`npm run check:document-parser` builds the pinned image and executes the actual stdin runner against the immutable 40-file corpus, 25 negative classes, boundary and isolation checks. It is included in `npm run check`. `npm run verify` retains all existing real service checks and then separately scans this candidate image with Trivy. The scanner analyzes the exported immutable image without a Docker socket, verifies recognized OS and pypdf packages and blocks HIGH/CRITICAL findings. These candidate results do not claim a fifth running production service. CI retains both raw test and scan JSON.

The image accepts one `pdf` or `docx` argument and binary stdin only. It writes exactly one UTF-8 JSON result to stdout. `ready` returns `body`, `locations` (`kind`, `unit`, half-open Unicode-codepoint `char_start`/`char_end`) and `source_page_count` (integer for PDF, null for DOCX). `needs_ocr` returns only status and PDF page count; one image-only page makes the entire mixed document `needs_ocr`. `failed` returns only status and a frozen `failure_reason`. Success/needs_ocr exit 0; failed exits 1; invalid CLI arguments exit 2. These are private component fields, not a new public HTTP response or a frozen network RPC. Body text is an intentional machine response, never a log entry.

The caller must run this image nonroot with network=none, read-only root, no capabilities, no-new-privileges, 512MiB memory (no swap), 1 CPU, 32 PIDs and a 64MiB noexec/nosuid tmpfs at /tmp. The check script applies and verifies this isolation. The CLI accepts no filename/path/URL or environment configuration; its parent creates a private temporary source file and removes it on normal success/failure. Container removal discards tmpfs after external termination. Each extraction runs in a fresh child: 384MiB address-space limit, CPU 30/31 seconds, 32 file descriptors, no core dumps. The parent enforces a 30-second wall budget and an 8MiB output-protocol cap, kills its entire child process group and waits for termination. Do not invoke this core directly in an HTTP process or database transaction.

Bounds: 10MiB input; PDF 200 pages and 32MiB decoded content streams; DOCX 2000 ZIP entries, 32MiB expansion, ratio 100, 20000 logical paragraphs; UTF-8 body 2MiB. Decompression itself can exhaust memory before a decoded stream can be counted, so the independent child/container limits are mandatory. A handles text-layer PDFs and ordinary DOCX paragraphs/tables only. Blank PDF pages are omitted from text while preserving source page numbers. Blank DOCX paragraphs consume logical unit numbers. The body changes CRLF/CR to LF and removes one initial BOM; it does not normalize, trim, correct or invent source words. Two LF characters separate nonempty source units. No PDF JavaScript, macro, OLE or external relationship is executed/fetched. Unsupported Word drawing/textbox/altChunk content is rejected. Legacy .doc and macro formats must be converted to ordinary .docx by the user; headers/footnotes/formula/complex visual reading order are outside this A core's supported scope.

Dependencies: pypdf 7.0.1 BSD-3-Clause, exact official wheel SHA-256 and Python 3.14.10-alpine3.24 official image digest in `requirements.lock` / `scripts/toolchain.json`. Standard-library ZIP/XML only for DOCX. The builder uses pip; the runtime actually removes unused pip/ensurepip code and bundled wheels. The pypdf license ships in its installed dist-info and is preserved in [dependency evidence](../reports/changes/04E/dependency-research/pypdf-LICENSE.txt); the base image preserves its own Python/system notices. No OCR/embedding/model dependencies are installed. Fixture fonts and their license are recorded under [testdata](testdata/acceptance-v1/README.md).

## Private HTTP adapter candidate

After reviewed #48 and #49, `server.py` provides the private I1 adapter as an explicitly launched component. The default ENTRYPOINT is still the offline CLI and default Compose does not start this service. Deployment must use an isolated internal backend/parser network without host ports, and set the approved canonical DOCUMENT_PARSER_TOKEN only in the process environment; invoke `python -B -I /app/server.py` inside that container. No default token or URL is introduced. Runtime config/Compose activation and the Go client remain pending, as do migration6 and the persistent queue. `test_rpc.py` runs actual loopback HTTP against the image under the original isolation and extracts the 40 fixed files through real child processes. Simulated failure mapping tests are reported separately from actual extraction; these tests do not prove database/queue or production wiring.

The following Go client component lives in backend/internal/documentparser and is still not imported by the default server. New accepts only the fixed reviewed origin and canonical token; transport disables proxies/redirects and applies the separate 500ms preflight and 35s parse budget. It rejects ambiguous JSON, status/body mismatch and invalid Unicode source locations before returning a ready result. The checker additionally compiles this actual client and runs it against the exact parser image in its own internal-only Docker network, with 40 real files, wrong-token and stopped-parser checks. Default configuration/network activation and the SQL-backed queue remain pending.
