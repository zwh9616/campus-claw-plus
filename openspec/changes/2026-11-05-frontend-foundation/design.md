## Decisions

### D1 页面、路由与角色

| 路径 | 可见范围 | 内容与操作 | 未认证/异常 |
| --- | --- | --- | --- |
| `/` | 公开 | CampusClawPlus、简短启动说明；登录入口；已认证显示“进入工作台” | 无业务API请求，无假统计 |
| `/login` | 未认证或恢复失败 | 用户名、密码、登录；显式错误与重试 | 已认证进入`/app`；恢复中不先闪现表单 |
| `/app` | 已认证师生 | 当前角色/班级ID；“当前仅开放账号与班级功能”及账号入口 | 恢复完成前不显示旧身份；无资料/作业等菜单或假数据 |
| `/app/account` | 已认证师生 | 账号ID、角色、当前班级ID；退出登录；教师可打开切班表单 | 学生不显示切班入口，不显示未冻结的个人资料 |
| 其他 | 公开404壳 | “页面不存在”、返回首页 | 不自动当成已存在业务页；不请求猜测API |

顶部品牌返回首页；已登录导航只含“工作台”“账号与班级”。教师切班用“目标班级ID”输入框，辅助文字“请输入你任教班级的ID，由服务端核验权限”。00没有班级列表/名称接口，故不造下拉选项、不试探枚举、不手写用户成员列表。该ID输入方案须小葛明确审查；若团队需要班名选择器，先由01/00补冻结合同再修02，不留实现人二选一。学生不提供任意班级输入。ID按字符串处理和显示，禁止转JS Number。

前端显隐只是体验；后端授权仍是唯一准入。教师/学生伪造客户端状态不能扩大权限。显示字段只来自有效AuthSession/GET me的Principal，角色文字固定“教师”“学生”。不知道姓名、班名时明确显示ID，不补虚构名称。

### D2 允许接口与认证状态

仅使用以下已冻结操作；响应按00单源Schema约束，不复制另一套不同字段：

| 操作 | 客户端责任 |
| --- | --- |
| POST `/api/v1/auth/login` | JSON username/password，成功200 AuthSession；只保存内存访问令牌和Principal，刷新Cookie由浏览器处理 |
| GET `/api/v1/auth/csrf` | 同源credentials，取会话CSRF到内存，不当匿名身份入口 |
| POST `/api/v1/auth/refresh` | 同源credentials与X-CSRF-Token，无body；成功替换内存AuthSession，再GET csrf |
| GET `/api/v1/me` | 当前Bearer；取得可信Principal，无body |
| POST `/api/v1/auth/logout` | Bearer、同源Cookie、CSRF；204无body才记服务端登出成功 |
| POST `/api/v1/auth/switch-class` | 同logout凭据，JSON class_id；200替换上下文及凭证，再取CSRF |

Origin由浏览器生成，不用JS伪造；同源HTTPS及Secure Cookie按01/10受审部署提供，不开通配CORS、降级HTTP或读HttpOnly Cookie。不从页面调用health做“系统健康”业务面板。planned路径禁止进入客户端请求表。

认证状态为`recovering / anonymous / authenticated / refreshing / changing-class / signing-out / recovery-error`。访问令牌、CSRF仅内存；不进URL、localStorage、sessionStorage、持久缓存、控制台、埋点或截图。不得在开发版本自动登录固定账号。

### D3 登录、启动恢复与刷新

页面重载进入受保护路径：先显示恢复中，GET csrf→POST refresh→GET csrf→GET me；全部身份步骤成功才显示受保护内容。无有效Cookie导致401则清空内存进入登录页；503/504/离线/格式错误进入恢复失败页，提供“重试恢复”“返回登录”，不无限转圈或宣称已登出服务器。返回登录只清本地状态，文案不冒充已撤销服务端会话。

登录字段有label、必填标识、username自动填充和current-password类型提示。用户名1..64、密码1..128 Unicode码点，原样提交，不trim密码或私改大小写；空/超长先本地提示，提交时完整校验。401统一“账号或密码不正确，或账号暂不可用”，不猜账号存在性；失败保留用户名、清空密码，焦点到错误摘要后可回字段。提交中禁重复操作；200后GET csrf准备后续操作，CSRF获取失败不伪装可正常切班/登出，转受控恢复状态。

同标签页只有一个refresh进行，其余需凭据的GET等待同一个结果；不循环刷新。一次受保护GET的401允许一次恢复尝试及一次GET重放，再401即清本地身份回登录。login/refresh/logout/switch等写动作不使用这个自动GET重试器，不自动重发不确定的POST。每次刷新后重新取得CSRF，不沿用旧值。expires_in=900用于提前显示会话即将到期和发起恢复，不代表客户端时间可以推翻服务端401。

多标签页不共享访问令牌。一次refresh的竞争失败401只清失败标签页本地状态，提示“会话已更新，请重新登录”，不能自动调用logout撤销赢家。标签页可广播不含令牌、CSRF、身份原值的“上下文已变”信号让其他页清缓存并进入恢复；不以广播代替服务器认证。每次页面重新可见及进入受保护路由重新验证me，遇401按上述有限恢复处理。安全失效不依赖广播必达。

### D4 登出、切班与过期请求隔离

统一对刷新、切班、登出串行化，禁止同一标签页同时发认证写操作。每次身份变化递增本地请求代号，取消旧请求并丢弃迟到响应；缓存按用户/班级/会话版本隔离。登出点击后立即隐藏私有内容，但在204前显示“正在退出”，不写成功。204清空所有内存和缓存，回登录；网络断开/超时不能确定服务端结果时显示“退出结果暂未确认”，保持私有内容隐藏，提供重新认证/恢复入口，不自动重发或谎称撤销。401视为当前凭据已失效并回登录，但不声称其他会话被撤销。

教师提交切班前校验00 ID字符串边界；期间隐藏当前班内容并禁重复提交。收到200时清旧班缓存、应用新Principal/凭证、重新取CSRF，然后进入工作台；旧班GET即使迟到也不得回填。403时显示“无法切换到该班级，请确认班级权限或重新验证会话”；服务端未提供细分码时不能猜是成员关系还是CSRF失败。确认失败且原会话仍有效才恢复原班显示。400映射字段错误；401清状态；503/504/网络丢包结果不确定时清本地上下文、进入恢复流程，先取得服务端真实身份再显示，不自行假定原班或目标班已生效。禁止重放切班POST。

切到当前班不发请求，仅提示“当前已在此班级”；不据此修改后端契约。学生直接访问账号页只读身份，伪造教师按钮也不能获得后端权限。切班/登出后旧页面、浏览器后退或恢复缓存不得重新显示失效私有内容，重新走路由身份校验。

### D5 错误、四态与可恢复操作

所有请求设客户端10秒截止（02候选体验值，不修改服务端预算）；到时终止本地等待并显示结果未确认，不能把客户端abort当服务端回滚。错误有文字、下一步和可复制的服务端request_id；不渲染原始HTML、SQL、堆栈或凭据。Error不符Schema、成功响应缺Principal或角色未知均视为受控错误，不能放行。

| 状态 | 页面表现 | 判定与动作 |
| --- | --- | --- |
| 正常 | 登录可提交；工作台/账号显示可信身份 | 真实操作只调用表列冻结端点 |
| 加载 | 文本“正在恢复会话…”/“正在登录…”；局部占位，不闪旧用户 | aria-busy；按钮禁重复；10秒内进入正常/错误 |
| 空 | 工作台目前无教学功能：“当前仅开放账号与班级功能” | 只有账号入口，不假造空资料API；Principal缺失不作为正常空态 |
| 错误 | 内联或整页错误、保留允许保留的输入 | GET可显式重试；POST按D3/D4处理不确定结果 |

400按已知字段贴近提示，未知字段错误放摘要；401按流程恢复/回登录；403不自动切班/降权重试；404未知页面独立处理；429显示等待秒数并禁止在有效Retry-After内重复提交，缺失/非法头时显示稍后手动重试，不猜固定间隔循环；503提示服务暂不可用；504/本地截止提示超时并按写动作不确定结果处理。认证操作未声明的错误码作为受控合同错误记录脱敏证据，不创造成功分支。

### D8 测试边界、交付和失败拦截

遵守campus-add-tests方法，将FEF-SC关联正常/失败/边界测试和证据。mock在测试进程明确启用，生产构建不可进入模拟身份/网络适配器；模拟数据覆盖过期、延迟、401/403/429/503/504、乱序和畸形响应。mock通过只表示客户端分支符合预期，不证明登录安全或DB事务成功。

真实联验必须G2+01真实服务可用，受信HTTPS同源、真实隔离MySQL、双班五人和多班教师；固定01后端SHA与02前端SHA，集成后再记录共同SHA。实际验证登录→me→刷新→切班→旧凭据失效→登出→再访问拒绝，并检查Cookie属性、CSRF、跨标签页竞争和原班迟到响应不显示。前端不能伪造MySQL/权限实测；服务端断言引用01同次证据。未接01时状态为待集成验收。

保留npm check（含生效后的合同检查）、audit、secret-scan与verify；新前端测试应接入同一门禁，工具选型/精确版本/许可由实现PR解释，不另建永远不跑的测试。测试必须实际断言路由、字段、请求次数、身份清理与无迟到回填；受控破坏“丢弃旧班响应”或“401拒绝放行”之一，观察测试非零，逐字节恢复并重跑，记录真实输出。七类核查：入口/业务状态/公共组件/错误/安全均有测试；数据库无前端直接访问，引用01联验证据；性能记录固定页面/网络与渲染耗时，02不擅自设全系统SLO，10另管运行阈值。视觉审查另记，不被CI绿色替代。

证据放reports/changes/02/：spec-check、样板确认、mock-results、real-auth-results、visual-manifest与红绿记录。每项写执行者、时间、代码SHA/脏树状态、环境、命令、预期/实际/退出码；未测写未验证。本规约提交只生成文档校验记录，不生成假截图或假运行报告。

## Risks / Trade-offs

只展示ID降低友好性，但避免虚构班级清单；未来可经合同变更扩展。多标签页refresh竞争可能要求失败页重新登录，遵循01单赢家，不为无感体验放宽撤销。网络丢包时无法仅凭前端确认POST提交结果，选择隐藏私有内容并重新取可信会话。公共配置/健康修改交00/01两人流程，本change不顺带改动已终审00范围。
