## 存储与原子边界

只加三张InnoDB表；实际列类型、完整DDL、索引、约束和摘要随实现提交审查，不能用此表冒充已执行SQL。

| 候选表 | 内容和必须守住的约束 |
| --- | --- |
| materials | 资料ID、class_id、创建者、规范化标题、固定版本1、状态、原始文件字节/长度、规范化正文、创建时间；关联现有用户/班级，禁止删除资料时级联删除身份；可按班级/状态/id过滤，材料id/class/version有组合唯一键供下游引用 |
| material_idempotency | user_id、class_id、ASCII大小写敏感的键、规范化标题+原始字节的摘要、资料ID/版本；唯一键为(user_id,class_id,key)，资料/班级/版本外键阻止错误关联；记录不自动过期，不存凭据 |
| material_chunks | chunk_id、class_id、material_id、version、ordinal、码点半开区间、quote；资料/班级/版本外键和该版本ordinal唯一；索引支持班级和资料版本过滤；不以片段自身的班级字段代替回查持久资料授权 |

ID延续01存储风格及00的正十进制字符串上界；对外输出不得转JS number。正文用utf8mb4、原始文件用二进制列。原文和索引只在本MySQL持久化；字面检索显式使用区分大小写的二进制比较和绑定参数，不能继承默认不区分大小写的LIKE或将`%/_`当通配符。测试须实测中文、非BMP与组合字符，码点偏移由规范化正文计算，不拿UTF-8字节偏移充当码点。

创建事务写materials、原始字节/正文和唯一重放记录，失败全回滚。资料提交后另开索引事务：按当前班级锁资料行，复查状态，写全片段并置ready一起提交；失败回滚片段，能确认当前状态时另记failed且不能覆盖并发ready。同键并发/事务提交结果未知时重查唯一记录；业务数据库5秒预算和503/504边界沿用01。学生仅可见ready，不能暴露处理中片段。

## DDL失败、前向修复及真实验收

1. 先停止本项目写流量，以持有人在本机运行环境提供的离线凭据做一致备份；不在命令行、日志或证据中放值。备份文件、证书、初始化输入和数据库内容不入Git。
2. `check`核对现有schema_migrations、历史摘要及实际结构。dirty、错/缺摘要、结构不符或未知更高版本必须非零退出，不能只看版本号。工具禁止自动force/down。
3. 按父表→幂等表→片段表的顺序添加；每一条真实DDL之后都设置可控中断点。MySQL DDL不可当作事务回滚：中断后记录真实version/dirty和实际结构，禁止删表重来。
4. `repair 4`只能用于当前对应版本，要求前3版摘要和结构完整；已存在对象逐列/类型/默认值/索引/唯一键/外键核对，完全相容才补缺对象，结构漂移继续失败。全部检查通过后才补真实摘要并清dirty，再运行离线check；已有资料和身份数据须保持。
5. 实现后分别验证空库→4、含两班五人身份数据的3→4、每条DDL中断→阻断→前向恢复、缺/错摘要与结构漂移仍阻断；再跑身份/会话回归、并发重放和索引中断恢复、MySQL重建后的资料/原文/片段保持。PR #26已按上述路径在真实MySQL执行成功，命令/版本/退出码见实现记录及原始JSON；持有人部署不能由CI结果自动推定。
